## Known Gaps Affecting These Requirements

These are implementation defects uncovered during reverse-engineering, not requirements changes.
They're tracked in `docs/plans/fix-review-findings.md` and are called out here so a status of
"Implemented" above isn't read as "defect-free":

- **FR-005 / NFR-007:** The PDF cache key backing NFR-007 is currently a predictable
  `time+nanoTime` string, not a cryptographically random value — hence "In Progress," with the
  fix and a matching update to UC-005's BR-013 tracked in the plan.
- **FR-005:** The `MODAL` question type is unimplemented (placeholder rendering only), and the
  "less than" branching operator is implemented identically to "greater than" — both latent
  defects in adaptive branching, not intended behavior (see UC-002 Notes/Known Gaps).
- **FR-008:** The Review page's Finish button reuses the Previous button's enabled/disabled
  condition, which is very likely a copy-paste defect (see UC-003 Notes/Known Gaps).
- **FR-011:** No post-survey action ever records a terminal "succeeded" status — success is only
  inferred from the absence of a recorded failure (see UC-004 BR-011).
- **NFR-004 / C-010:** TLS-in-transit and PHI-handling posture depend on how this application is
  deployed (reverse proxy/ingress termination, hosting environment) and cannot be verified from
  the application codebase alone — marked "Open" pending confirmation against the actual
  deployment configuration.
- **FR-023:** Service-layer error messages (PDF generation, report services) are still produced in
  English and shown verbatim; localizing them needs a message-key carrier on the exceptions and is
  planned as a follow-up to the UI chrome localization (UC-009).
